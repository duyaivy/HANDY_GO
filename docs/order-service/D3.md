# D3 — Messaging và tích hợp

## Mục tiêu và phạm vi

Xử lý BE-04, BE-05, BE-06, BE-07, BE-11a và BE-11b sau D2. Đảm bảo payment consumer hoạt động và event Order tương thích Bidding/Notification. Có regression test và commit riêng.

## Thực hiện

- **BE-04:** Kết nối RMQ listener cho queue Order trong entrypoint bằng `createRabbitMQOptions` và `connectMicroservices`; kiểm tra cấu hình ACK của listener và topology thực tế.
- **BE-05:** Ghi consumed event và cập nhật `paymentState` trong cùng transaction; ACK sau commit. Khi lỗi DB rollback cả hai và NACK/requeue; duplicate hợp lệ được ACK. Dùng event ID ổn định từ producer, không tạo ID bằng `Date.now()`. Event thiếu ID hoặc orderId được log và từ chối không requeue, tránh vòng lặp vô hạn; kiểm tra cấu hình DLQ thực tế.
- **BE-06:** Bọc packet từ outbox bằng envelope Notification gồm event ID từ record, event type/version, source `order-service`, occurredAt và payload. Giữ ID/thời điểm qua retry; kiểm tra hình dạng packet thực phát tương thích cả Notification và Bidding.
- **BE-07:** Gửi `selectedBidId` từ Order và `workerId` tương thích Bidding trong `order.created`, giữ các field hiện có cần cho consumer khác. Với nguồn recommendation không tự tạo bid ID.
- **BE-11a:** Ghi `booking_proposal.created`, `booking_proposal.changes_requested`, `booking_proposal.rejected` trong cùng transaction với thay đổi proposal; payload và recipient phù hợp contract Notification.
- **BE-11b:** Phát `order.status.changed` với `previousStatus`, `nextStatus`, `notificationKind` theo contract Notification cho tiến trình. Dùng event chuyên biệt completed/cancelled làm đường notification duy nhất cho hai trạng thái đó; giữ domain event khác nếu consumer cần.

## Contract và kiểm thử

- Chạy entrypoint Order thật với RabbitMQ, publish `payment.succeeded/failed`, xác nhận Order đổi payment state; thử duplicate, thiếu ID/orderId và lỗi DB lần đầu rồi retry cùng event.
- Test rollback inbox + update và ACK/NACK đúng thời điểm; kiểm tra lỗi không gây mất event.
- Đưa packet thực tế qua `validateNotificationEvent` và consumer/router Notification; xác minh proposal và tiến trình đến đúng recipient, không tạo thông báo đôi khi completed/cancelled.
- Đưa `order.created` qua consumer Bidding: bid A được selected, bid active khác rejected; recommendation không giả thành bid thắng.
- Kiểm tra retry outbox giữ event ID/thời điểm và xử lý idempotent. Kiểm tra rollback không phát event nếu transaction nghiệp vụ thất bại.

## Hoàn thành

Unit/contract test và kiểm thử DB/broker liên quan đạt; ghi rõ test chưa chạy nếu hạ tầng thiếu. Cập nhật registry `backend/AGENTS.md` khi thay đổi component reusable. Commit D3 riêng.
